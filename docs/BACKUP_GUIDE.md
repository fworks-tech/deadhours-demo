**Author:** Fabio (Solo Indie Developer)  
**Last Updated:** September 16, 2026  
**Projects Covered:** *Dead Hours* (`dead-hours/`) and *Dead Hours: Visitor* (`visitor/`)

---

## 1. Overview & Strategy

As a solo indie developer, protecting game source code, custom art assets, dialogue databases, export configurations, and project metadata against data loss or corruption is critical. 

This guide defines the standard manual backup procedures, archive naming conventions, cloud folder structures, disaster recovery protocols, and recommendations for automating monthly scheduled backups.

---

## 2. What to Back Up

Backups must capture all essential source files, assets, and project configurations required to resume development immediately on a clean machine.

### Target Folders
1. **`dead-hours/`** (*Dead Hours* main project):
   - `.godot/` (optional, can be regenerated by Godot on import, but excluding `.godot/` saves significant zip size and zip time)
   - `assets/` (portraits, backgrounds, audio, fonts, sprite sheets)
   - `autoload/` (global singletons: `StoryManager.gd`, `FlagsManager.gd`, `SaveManager.gd`, `BackgroundManager.gd`, `AudioManager.gd`)
   - `scenes/` & `scripts/` (UI, cutscenes, dialogue system, exploration)
   - `locale/` (localization files)
   - `docs/` (art pipeline, story guides, export configurations)
   - `project.godot` & `export_presets.cfg` (CRITICAL: contains all project settings and mobile export keystore configurations)

2. **`visitor/`** (*Dead Hours: Visitor* concept/prototype):
   - `assets/` (uncanny portrait concepts, inspection tables, CRT shaders)
   - Scenes, scripts, and documentation files

### Exclusion List (To Keep Zip Clean & Lightweight)
- `.godot/` directory (Godot's local cache / import artifacts — will automatically re-import PNGs/WAVs when opened)
- `build/` or `.apk` / `.aab` / `.ipa` binaries (build outputs can be re-exported anytime; save cloud storage space)
- OS temporary files (`.DS_Store`, `Thumbs.db`)

## 3. Naming Convention

All backup zip archives must adhere to the standardized naming scheme:

```
{ProjectName}_v{Version}_{YYYY-MM-DD}.zip
```

### Examples
- **Dead Hours:** `DeadHours_v1.0.0_2026-08-09.zip`
- **Dead Hours (Milestone build):** `DeadHours_v1.1.0-alpha_2026-09-01.zip`
- **Visitor Project:** `Visitor_v0.1.0_2026-08-09.zip`
- **DEEPTALES Framework:** `DEEPTALES_v1.6.0_2026-09-16.zip` (the `deeptales/` generator framework + PROGRESS.md — back it up after any generator/blueprint change)

## 4. Current Manual Backup Process

### Step 1: Create Compressed Zip Archives
From the command line in the parent workspace directory (`/app/conversations/6a6d50eb4bc0607c48538714/`):

```bash
# Archive Dead Hours (excluding build artifacts and local .godot cache)
zip -r DeadHours_v1.0.0_$(date +%Y-%m-%d).zip dead-hours/ -x "dead-hours/.godot/*" "dead-hours/build/*"

# Archive Visitor Project
zip -r Visitor_v0.1.0_$(date +%Y-%m-%d).zip visitor/ -x "visitor/.godot/*" "visitor/build/*"

# Archive DEEPTALES framework (after generator/blueprint changes)
zip -r DEEPTALES_v1.6.0_$(date +%Y-%m-%d).zip deeptales/ PROGRESS.md -x "*__pycache__*"
```

**Automated path (preferred):** the studio agent can zip + upload to the
correct Drive folder on request — just ask it to "push backups to Drive".
Current versions: Dead Hours **v1.1.0**, Visitor **v0.1.1**, DEEPTALES **v1.6.0**.

Or via local file explorer:
1. Right-click `dead-hours/` folder.
2. Select **Compress to ZIP** / **Send to Compressed Folder**.
3. Rename the resulting zip following `DeadHours_v{version}_{date}.zip`.
4. Repeat for `visitor/`.

1. Open Google Drive web browser or desktop sync client.
2. Navigate to the targeted cloud folder structure (see Section 5 below).
3. Drag and drop the `.zip` files.
4. Verify file upload size and completion status.

## 6. Disaster Recovery Process

If local files are lost, corrupted, or when migrating to a new development workstation:

1. **Download Archive:** Download the latest `ProjectName_v{version}_{date}.zip` from Google Drive.
2. **Extract:** Extract the zip into your local Godot workspace directory.
3. **Verify Keystores:** Ensure `release.keystore` or `debug.keystore` paths referenced in `export_presets.cfg` are present.
4. **Launch Godot Engine (Godot 4.x):**
   - Open Godot Project Manager.
   - Click **Import** and navigate to the extracted folder.
   - Select `project.godot`.
5. **Initial Re-Import Phase:**
   - Allow Godot 2-5 minutes to re-import assets (images, audio, fonts) and rebuild the `.godot/` import cache.
6. **Verification Checklist:**
   - [ ] Run Main Scene (`F5`) to verify start menu and UI load without missing resource errors.
   - [ ] Open `scenes/CutsceneTemplate.tscn` and verify background textures render.
   - [ ] Check `Project -> Export...` to verify preset configurations exist and keystore paths are valid.

## 7. Automated Scheduled Backup Recommendation

While manual backups work for sporadic milestones, relying solely on manual steps introduces risk of forgotten backups during active development phases.

### Recommendation: Monthly Scheduled Workflow
Set up an automated monthly scheduled workflow (via script or CI/CD workflow):

1. **Automated Zip & Backup Script:**
   Create a local/CI bash script (`scripts/backup.sh`):
   ```bash
   #!/bin/bash
   DATE=$(date +%Y-%m-%d)
   ZIP_NAME="DeadHours_v1.0.0_${DATE}.zip"
   
   echo "Creating backup ${ZIP_NAME}..."
   zip -r "${ZIP_NAME}" dead-hours/ -x "dead-hours/.godot/*" "dead-hours/build/*"
   
   # Optional: Upload using rclone / gdrive CLI to Google Drive
   # rclone copy "${ZIP_NAME}" gdrive:"Fabio Game Dev Projects/Dead Hours/Source Backups/"
   ```

2. **Git / GitHub Remote Repository:**
   - Pair monthly zip backups with a private GitHub repository for daily source code versioning (`git push`).
   - Use `.gitignore` to exclude `.godot/`, `build/`, and `*.keystore`.
   - Store large raw media assets (LFS) in Google Drive backups while keeping code in Git.
